# S1 鉴权 API 与 SDK 验收

日期：2026-10-06。本切片接通 HTTP 控制面契约与数据库服务；不表示完整 S1 或真实执行入口已开放。

## 实现与范围

Job 创建/查询、Worker 领取/续租/结果提交均使用共享 Schema。owner 与 worker_id 来自 Bearer 凭证认证，不能从请求指定。凭证配置只保存摘要、身份和角色，原始 token 不入库；错误响应不回显配置、非法输入、SQL 或原始 SDK 错误。

控制面写接口默认关闭，无鉴权配置时禁止启用写接口。USER 与 WORKER 权限分离；跨用户查询返回 404，错误 Worker 提交返回 409。相同内容幂等，不同内容冲突。

OpenAPI 离线导出与前端类型已经生成，并接入 make check / CI 的一致性检查。未新增业务页面或真实 Worker。

## 本地证据

使用独立临时 PostgreSQL 16.15 容器；每项数据库测试使用独立 schema。测试 token 均在运行时随机生成，不使用真实用户或模型凭证。

5 项真实 PostgreSQL + ASGI 路由/SDK 测试通过：

1. SDK 创建、查询、领取、续租、零分完成及幂等重放闭环；空队列返回 None。
2. 跨用户查询、USER/WORKER 越权、错误 Worker 续租/提交均拒绝；伪造身份与意外敏感字段拒绝，错误不回显输入。
3. 配置冲突、非法租约时长、过期提交及关闭写入口的拒绝语义。
4. OpenAPI 中 Bearer 声明完整；请求模型不允许 owner_id 或 worker_id；即使测试开启元数据写开关，execution_enabled 仍为 false。
5. 在测试 schema 删除 executions 表注入故障，领取返回安全 503，事务回滚后 Trial 保持 QUEUED。

另外 7 项认证测试、5 项 SDK 错误处理测试通过。验证未知与缺失凭证、角色隔离、启动配置无效与重复摘要拒绝、重定向不跟随、网络/响应错误清理，以及禁止在 SDK 地址中嵌入认证信息。

带真实 PostgreSQL 运行 make check：88 项测试全部通过，无跳过；Python lint/格式、OpenAPI 一致性、前端生成类型一致性、TypeScript 和构建通过。

make runtime-check 的 8 项固定版本依赖契约检查通过；Worker/Scheduler 的 --check 骨架检查通过，不能当作真实执行进程验收。

## 边界

HTTPX 使用 ASGITransport 调用真实 FastAPI 路由，数据库为真实 PostgreSQL；没有 Mock 执行服务。该验收不覆盖跨进程 HTTP 网络、TLS、反向代理、浏览器登录或外部认证。

本阶段使用启动时加载的静态凭证，配置更新/撤销需要重启。尚无用户登录、OIDC 或租户 Worker 分配。SDK 使用的原始响应不进入异常文本，但调用方仍应避免主动记录认证头。

没有运行 Harbor/E2B/模型，因此不能作为新增真实 Rollout 验收。下一切片补齐可运行快照、真实 Worker 与对象存储存在性/摘要/上传恢复验证；S0 与 S1 剩余关卡未全部通过前，继续保持真实执行入口关闭。
