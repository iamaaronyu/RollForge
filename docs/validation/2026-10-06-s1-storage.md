# S1 对象存储与恢复验收

日期：2026-10-06。本聊天按用户指定负责对象存储与恢复，Worker、Hub API 接入由并行 Agent 负责。本记录不是完整 S1 或 Worker 新建 Sandbox 的全链验收。

## 交付

共享 ArtifactManifest、ExecutionScope、StoredFile 契约位于 packages/schemas/storage.py。独立 rollforge-object-store 包提供 S3 条件写入、全内容读回、BundlePublisher 预检/发布/远端恢复；接口和恢复步骤见 [存储包说明](../../packages/object-store/README.md)。

对象键属于 Job/Trial/Execution，Retry 使用新 Execution 前缀。文件全部读回验证后才发布最终 Manifest；重新上传只接受完全相同的内容，不覆盖冲突对象。Manifest 保存 fencing token，调用方仍必须经过 PostgreSQL 当前租约检查。

本次范围：每文件 64 MiB、每 Execution 128 MiB、512 个文件，UTF-8 相对路径最多 768 字节。拒绝符号链接、非普通文件、非规范路径和凭证文件；已知凭证的文件内容/文件名命中会在上传任何对象前拒绝。上传时重新核对预检摘要，文件变化不能发布 Manifest。远端恢复从原始 result.json 重新解析汇总，伪造 Manifest 评分不能被接受。

## 真实环境

本机 Docker Hub 与 Quay 均拒绝拉取项目原固定 MinIO 镜像；官方历史 darwin-arm64 下载地址返回 410。因此从 MinIO 官方源码固定 RELEASE.2025-04-22T22-12-26Z 构建，Go 模块版本为 v0.0.0-20250422221226-0d7408fc9969，工具链 go1.24.2 darwin/arm64。go install 未注入发布版本字符串，二进制 --version 显示 DEVELOPMENT.GOGET；不以此字符串声称获得官方发布二进制。

构建、二进制与日志保存在忽略目录。每项集成测试使用真实本机 MinIO、随机临时管理员凭证、独立随机 bucket。只监听 loopback，不复用现有数据目录；测试结束清理自己的 bucket 和进程。服务进程没有继承模型或 E2B 凭证。

## 已通过证据

22 项边界测试通过，包括写入后响应丢失重放、上传期间文件变化、凭证文件名/内容命中、文件/目录符号链接、规范路径、结果汇总篡改、SDK 错误清理及禁止带凭证地址。

6 项真实 MinIO 验收通过：

1. 两个并发不同内容的条件 PUT 仅一个成功，同内容可重放。
2. 首个文件实际写入后注入响应丢失，Manifest 不存在；新 SDK 客户端重放全部上传成功。删除本地输出后仍可从远端恢复相同 ResultCommit。
3. 完整上传后停止并重启同一独立 MinIO 进程，新客户端读回及摘要验证通过。
4. 管理员直接篡改或删除原始文件，完整验证拒绝。
5. 新 Execution/新 fencing token 使用独立对象键，旧 Manifest 摘要不能作为新 Execution 的结果。
6. 使用 S0 已完成主机重启验收的真实 Harbor 输出（16 个文件、评分 1.0），先扫描本地模型/E2B 凭证值，再上传到独立 MinIO 并完整读回，得到相同 ResultCommit。没有在本测试中重新调用模型或创建 Sandbox。

仅包含本批存储代码的独立提交快照通过 28 项测试（22 项边界测试 + 6 项真实 MinIO），依赖锁离线一致性检查通过。

完整 `make check` 通过：118 passed、17 skipped；跳过项为未提供专用数据库地址的 PostgreSQL 测试。前端类型检查与生产构建通过。`make runtime-check` 的 9 项固定 Runtime 契约检查通过，不能替代真实 Worker 全链验收。

## 补充：真实上传进程强制终止

继续验收时新增两个真实 MinIO 场景，存储集成验收累计 8 项通过。上传在独立 Python 子进程运行，仅通过私有 stdin 管道提供随机测试凭证，不继承模型、Hub 或 E2B 环境变量。

- 第一个文件条件写入并读回后，用 SIGKILL 终止上传子进程，确认进程退出码为 SIGKILL、文件已在真实 MinIO 中且 Manifest 未发布；另一个进程内的新 SDK 客户端重放上传成功。
- Manifest 条件写入并读回、publish 尚未返回时，用 SIGKILL 终止子进程；另一个进程内的新 SDK 客户端直接从远端 Manifest 恢复 ResultCommit，无需重放上传。

两项恢复完成后删除本地原始输出，远端内容校验仍返回相同零分结果。检查点位于真实 PUT 之后，没有用 Python 异常代替进程终止。这覆盖对象上传进程死亡，未覆盖 Worker/Sandbox 中断、主机断电或数据库终态提交。

本批完整 `make check` 通过：120 passed、17 skipped（专用 PostgreSQL 环境未提供），前端类型与构建通过；`make runtime-check` 的 9 项契约检查通过。公开文件已扫描本地已知凭证值，命中为 0。

## 补充：存储与 Hub 提交联合恢复

两项联合验收使用真实独立 PostgreSQL 16、真实 MinIO 和带随机 WORKER token 的 Hub ASGI 应用，通过公开 SDK 调用领取及完成提交 API。使用经过存储校验的合成零分原始结果，不创建 Sandbox、不调用模型；Task/Agent/Model 绑定仅用于触发可运行执行的存储校验事务。

1. Hub 已完成数据库提交后，在 SDK transport 层关闭并丢弃成功响应，注入 ReadError；SDK 确实收到 HubTransportError。确认 PostgreSQL 已保存 COMPLETED 和同一 ResultCommit，再令租约过期、删除远端 Manifest、断开数据库连接并重建 Hub 应用及 SDK。相同提交仍幂等返回；修改已接受评分的提交被 CONFLICT 拒绝。这是实际提交后的客户端响应丢失注入，不是网络设备中断或 Hub 操作系统进程重启。
2. 旧 Execution 完成真实上传后，在 PostgreSQL 中使租约过期并执行有界回收。新领取保留 Trial、生成新 Execution 并递增 fencing token。旧 Manifest 仍能完整校验，但旧执行提交返回 HTTP 409 / LEASE_REJECTED，不改变新执行 RUNNING 状态；新 Execution 使用独立对象键，提交零分后得到 COMPLETED，旧对象内容仍保持可验证。

测试为每项分配随机独立数据库 schema 和 bucket，结束仅清理自身资源。专用 PostgreSQL 使用临时容器、随机凭证、loopback 随机端口和临时内存数据目录，与另一 Agent 的环境分离。该证据不替代真实 Worker 中断或新 Sandbox Retry 验收。

串行复检的完整 `make check` 通过：139 项 Python 测试全部通过、无跳过，前端类型与生产构建通过；`make runtime-check` 9 项通过。验收结束停止并删除本轮专用 PostgreSQL 容器及凭证配置，MinIO fixture 自动清理服务与 bucket。公开文件凭证扫描命中为 0。

## 剩余边界

响应丢失是实际 PUT 或 Hub 提交后的客户端故障注入，不是网络设备断电；部分上传恢复仍需要原始本地文件。已发布 Manifest 的恢复不依赖原始文件。本记录已覆盖存储与 Hub 事务联合恢复、租约失效拒绝；Worker SIGKILL、Sandbox 清理和新 Sandbox Retry 仍由 Worker 全链验收覆盖。

不提供 multipart、垃圾回收或 STS。条件写入是 SDK 协议约束，生产存储授权仍需禁止无条件覆盖/删除与跨租户访问；管理员可绕过 SDK 的情况用于篡改测试，不作为生产权限模型。测试使用现有固定版本仅在隔离的 loopback 环境验证 S3 兼容性，不据此选择生产存储发行版。Hub 真实执行入口仍等待完整切片验收。
