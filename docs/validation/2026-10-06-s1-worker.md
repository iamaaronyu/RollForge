# S1 Worker 实现与验证记录

日期：2026-10-06。范围：单 Trial 可运行快照、独立固定版本 Runtime 子进程、上传后元数据提交与本地恢复。对象存储实现及真实存储恢复验收由另一开发聊天负责。

## 已实现

- packages/schemas 定义不含凭证的 RunnableBinding，固定 Claude Code 2.1.81、Anthropic Messages、deepseek-flash、网关根地址和 separate verifier；Agent/Model Revision 摘要与绑定强制一致。
- claim 的 runnable_only 过滤元数据 Job；租约返回 job_id。Worker 每次领取一个 Trial，300 秒租约，每 30 秒续租。
- Task 归档摘要及规范内容摘要双校验；拒绝越界路径、链接、特殊文件和超预算归档。
- Runtime 使用独立 Python 和限定环境；Hub/S3 凭证不传给子进程。网关必须匹配 Worker 配置，默认 HTTPS；LAN HTTP 需显式启用。
- 使用实际安装的 Harbor 0.24.0 Trial.create / Trial.run 和 TrialResult；Harbor 负责 Sandbox 生命周期。Worker 取消时发 SIGTERM 并等待 Harbor 清理。
- 原生结果校验和任务不可变复核后才标记可上传；平台不伪造 Harbor 原始结果。
- 对象存储发布 Manifest 后落盘 pending-commit；Hub 在持有租约行锁的事务内验证对象作用域、token、摘要、文件和结果汇总，提交前再次核对数据库时钟。
- --resume 只重试已有产物的上传/提交，不重跑同一 Execution；提交响应丢失可幂等重放。
- OpenAPI 和前端类型重新生成；默认执行开关关闭，platform.execution_enabled 保持 false。

## 验证证据

1. 15 项 Worker 离线边界测试通过：Task 往返与可执行语义、越界/链接拒绝、私密文件权限、子进程凭证白名单及禁止变量展开、冻结版本摘要、默认禁用、租约丢失等待清理、网关绑定及 HTTP 显式开关、提交响应丢失恢复及身份不匹配拒绝。
2. 真实 PostgreSQL 16 专用临时容器：既有租约/API 验收 13 项，加 Worker 事务验收 3 项，共 16 项通过。另有 1 项真实 MinIO + PostgreSQL + 鉴权 API 联合验收通过（合计 17 项）：缺失 Manifest、伪造评分返回 503 且不写终态，真实上传的零分接受，删除 Manifest 后已接受提交仍可幂等重放。新增用例验证 runnable 过滤、对象验证异常回滚、已接受重放不依赖再次读取存储、错误身份在验证前拒绝、验证期间过期在提交前拒绝。注入的验证回调只测试事务边界，不算真实对象存储或模型验收。
3. make runtime-check：9 项真实已安装依赖契约检查通过。新增检查使用 Harbor 真实 Task 模型，拒绝未显式 separate verifier 的任务，并验证固定 CLI 和 Harbor delete 配置；不创建 Sandbox。
4. make check：Python lint/格式、API 导出一致性、Python 测试、前端类型及构建通过。使用另一开发聊天从固定源码构建的真实 MinIO 二进制，初轮 134 项 Python 测试全部通过，没有跳过；存储依赖提交后的复检为 138 项通过、1 项历史 Harbor 产物测试因未提供路径跳过（该项在存储侧已单独验收），前端类型检查及构建通过。

## 尚未通过的验收

真实 Worker → Hub → Harbor → 自托管 E2B → 受限模型网关 → separate verifier → 对象存储 → Hub 终态全链尚未运行。此前 S0 临时模型网关会话和网络例外已清理。本轮已准备恢复单地址、单端口策略的可审查脚本；Linux SSH 无免密 sudo，需要 owner 启用并在验收后恢复策略。模型上游 Key 只留 Mac，网络就绪后才能创建本轮受限会话。不能以离线测试或 PostgreSQL 测试代替。

还需在批准的单并发环境验证真实评分、零分、Worker 中断与清理、上传/提交恢复及有界 Retry；通用调度、Task Registry、批量展开、完整用户界面不在本切片范围。当前实现只接受经审核的任务，未验证未知任务的多租户安全隔离。

操作步骤和限制见 [Worker 说明](../worker.md)。切片 5 标记为“实现完成、真实主链验收待完成”，不宣称完整 S1 已完成。
