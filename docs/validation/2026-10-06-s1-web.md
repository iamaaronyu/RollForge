# 单任务页面与查询验收

日期：2026-10-06。本批实现分页 Job 列表、Execution 历史、服务端审核目录及中文创建/详情页面，保持正式执行入口关闭。

## 已完成

共享 JobList/JobSummary/ExecutionList/ExecutionView 与审核目录请求/响应定义在 packages/schemas。API 按 USER 身份过滤，分页每页最多 100 条；Job 列表不返回配置快照，Execution 历史不返回 worker_id。历史按 fencing token 递增，展示旧 Execution 的 EXPIRED 和新执行 RUNNING。

Hub 启动时加载 0600 普通文件中的冻结审核目录，校验契约/运行绑定/重复 ID 和 1 MiB 上限。目录接口仅返回 id/label；创建只接受 job_id/task_id，从服务端目录选择快照，浏览器不能注入 runtime 或 snapshot。它是临时审核配置，不代表通用 Registry 已完成。

Next 页面 /jobs、/jobs/{job_id} 使用生成类型。USER token 只在 server-only 调用层；创建使用 Server Action，默认关闭 Web 实验开关并保留 Hub 写开关。此页面为 loopback 单用户实验，不提供多用户登录。配置与边界见 [界面说明](../web-console.md)。

## 真实验证

使用本轮新建的 PostgreSQL 16 临时容器、随机端口/凭证；单测与数据库测试共新增 8 项通过：用户范围分页、游标重放顺序、limit 边界、WORKER 越权拒绝、跨用户历史 404、Retry 历史与 Worker 身份排除、审核目录服务器快照创建和幂等、禁止快照注入，以及私密目录安全读取与错误不泄漏。

真实浏览器连接 loopback Next 开发服务和 HTTP Hub，在下拉框选择合成审核任务后点击“创建 Job”，实际跳转到新 UUID 详情并显示“排队中”和空执行历史；回到列表看到新记录。另一条预置合成零分记录显示“已完成 / reward：0”，详情显示真实数据库中的 Execution 历史。页面截图和临时运行记录仅保存在测试过程，不提交运行数据。

上述三份渲染页面均返回 HTTP 200，响应内容对本轮 USER token 及 runtime 网关地址检查均为 0 命中。没有启动 Worker、E2B 或模型；预置评分用于页面显示验收，不冒充真实 Harbor 评分。底层主链真实证据仍见 [Worker 验收](2026-10-06-s1-worker.md)。

完整 make check：148 项 Python 测试全部通过、无跳过（提供真实 PostgreSQL、MinIO 和已有 Harbor 产物路径），OpenAPI、前端生成类型、TypeScript 与生产构建通过；make runtime-check：9 项通过。首次临时环境启动的自动审批超时，未执行；拆分脚本与启动命令后批准并完成验收。
